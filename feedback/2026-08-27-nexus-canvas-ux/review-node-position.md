# 节点位置迭代 · 设计评审（评审席交付 · 2026-08-28 · 状态：已裁决 → 方向 A）

> 起因：PR B（2D 规划模式）落地后，用户指出"3D 视角中节点位置迭代问题需进一步评审"。
> 依据：`nexus-stage/src/main.ts`（cycle 座位与创建时一次性读布局）、`nexus-stage/src/world.ts`（planSeatFor）、
> `src/layout-store.ts`（v1 契约）、实测取证（本文件 §2，脚本化复现于 mockhost + 活宿主代理）。

## 1. 现状：位置数据流矩阵

| | 2D 规划 | 3D 观测 |
|---|---|---|
| **写** | 拖拽 → 800ms 防抖 POST → 采纳归一化回包 | 无（观测不写，§1 双模裁决） |
| **读** | saved → 卡中心；未保存 → `planSeatFor`（三环 150/290/430） | **仅 mesh 创建时一次**；saved → `(x, 0, z)`；未保存 → `seatFor`（极环 12–30，y±1） |
| **单位** | px（卡宽 172） | 场景单位（节点半径 ~0.9，网格 120×120，相机 (0,35,55) maxDistance 180） |
| **会话中更新** | 实时（keyed diff + 保存回路） | **从不**（除 page reload） |

## 2. 实测证据（mockhost 8780 代理活宿主，5 节点舰队）

- **2D 拖一张卡 +700,+400 屏幕像素**（世界增量 ≈ +529,+303）→ 保存文档 nodes x∈[-615, 346]——只是"适度排布"。
- **切到观测：5 个节点仅 1 个在视口内**，4 个标签 rect 在 x=-2092…2212（相机外）。3D 场景近乎空场。
- **把卡拖回原位（文档坐标复原）后切观测：5 个标签矩形逐像素不变**——3D 对会话中的布局更新完全失明，只有 reload 才复活。

## 3. 问题清单

| # | 问题 | 严重度 |
|---|---|---|
| P1 | 2D 排布的坐标原样成为 3D 世界坐标，数百单位即飞出网格/相机——**2D 排布一次，3D 视角空场** | 高（实测） |
| P2 | 单位语义冲突：同一文档，2D 计 px（卡 172），3D 计场景单位（节点半径 ~0.9）——P1 根因 | 高（根因） |
| P3 | 3D 仅在 mesh 创建时读布局，会话中 2D 的保存对 3D 不可见（实测逐像素不变） | 中 |
| P4 | 未保存态座位分歧：`planSeatFor` 三环 vs `seatFor` 极环——保存前两模式各说各话（PR B 的可用性取舍，提请追认） | 低 |
| P5 | 单位不确定性：v1 契约未定义 `{x,y}` 的计量单位与用途（3D 已按 (x,0,z) 消费，2D 按平面中心消费）——契约空洞 | 中（文档债） |

## 4. 方案

### A. 3D 重投影（推荐）
3D 读 saved 布局时**只取相对结构，不取绝对量纲**：点云质心平移到原点 + 等比缩放进观测包络（如最大半径映射到 ~20，即极环尺度），每 poll 重算（顺带修 P3：已有 mesh 直接位移到目标位，零缓动教义）。2D 的排布在 3D 里呈现为"同样的拓扑关系、观测友好的尺度"。
- 优点：零契约变更；两模式各自可用；2D 仍是唯一排布真源；实现小（一个纯函数 + cycle 三行）。
- 代价：放弃跨模式度量保真（两模式本就是两种镜头——拓扑观赏 vs 几何排布）。

### B. 统一量纲 + 3D 自适应取景
认定 2D px 即场景单位，3D boot/poll 时 fitView 到 saved 点云（相机距离、网格尺寸随之缩放）。
- 优点：跨模式保真。
- 代价：3D 的雾效/灯光/LOD/网格全部要跟随尺度自适应，改动面大；2D 视口也要约束在合适量纲；实质是把 3D 变成 2D 的跟随视图，观测模式的"氛围语言"受损。

### C. 契约 v2 分层存储（nodes2d / nodes3d 分开）
- 优点：语义最干净，各存各的真。
- 代价：动锁定契约（canvas-ui-contract v1 + layout-store v2）+ host PR + 双端迁移，重；且"3D 排布"仍不存在，3D 座位还是得自动生成——分层收益存疑。

### D. 维持现状，只修 P3
- 最省，但 P1 实测仍在：2D 一次排布就把 3D 打散，不可接受。

## 5. 推荐

**A**（重投影 + P3 顺带修），同时：
- 追认 P4：两模式未保存态各自座位是"两种镜头"教义的自然推论；首次保存后收敛到同一文档。
- 补 P5 文档债：在 `docs/canvas-ui-contract.md` 增补一段"{x,y} 为 2D 平面卡中心，px 计；其他消费方须自行重投影"——把 A 的裁决写进契约，防后续消费者再踩。

## 6. 验收门草案（裁决后实施时用）

1. 2D 任意排布（含 +700 屏幕像素拖拽）后切观测：**5/5 节点在视口内**，拓扑关系（同队相邻性）与 2D 一致。
2. 会话中 2D 保存后，观测在下一次 poll 内跟随（label rect 变化可测）。
3. 未保存新节点两模式各自座位确定性不变（既有单测继续绿）。
4. 契约增补段落合并进 canvas-ui-contract.md（版本锁内补文档，不改形状）。
