## 三、四问裁决

### Q0（提案外，前置）作者席出站归因自证

"未加入会话经 a2a_route 成功投递"在当前 master 上仅有两条通路：**(a)** 出站席
即该 home 的 initiator 会话（豁免③——initiator 是节点本体，其出站属节点行为，
caller label 归因已在）；**(b)** 该 home 插件 <0.5.33 或未重启（滞后，非语义缺
口）。请作者席一句话回执走哪条：(a) 则见 Q4 附注的收敛讨论；(b) 则升级 home 即
闭，无需任何裁决落地。

### Q1 子代理/委派会话归属 —— **维持拒绝；"继承父 join"另立不捆绑**

子代理持独立 agent id、不在 `sessionNodes` → 现网已拒，且本席裁定**维持**：
委派工作流的出站应由父会话代为路由（caller label 的宿主+会话标识归因完整保留，
回执债按 !55 生债闸记账）。理由：join 是用户手势，按会话树授予而非逐会话复制，
边界清晰且可审计。若未来出现子代理直出的真实需求（流式回传等），走"继承父
join"独立设计（父 live-joined 或 `joinedSessions` 含父 id → 放行、归因透传），
以单独提案评审——不随本提案落地。

### Q2 存量迁移 —— **发版即断，无静默期**

安全边界变更不做 warn-then-enforce 宽限（静默窗口即攻击面）。发版说明标注
**BREAKING**；拒绝错误已自带加入指引（结构化、模型可见）；a2a-nodes 技能与
README 的"已知局限"措辞随发版同步（= F6 残余②，已在案）。多席未加入仍出站的
现状在 0.5.33+ 上本不应存在——各 home 自查版本与 initiator 身份即可，无需迁移
机制。

### Q3 测试面 —— **主战场在 join-gate.spec.ts，apply.spec 主体不翻改**

- 现网已钉：`join-gate.spec.ts` 三态 + apply.spec:442 外部 id 拒绝钉；e4bc635
  落地时 apply.spec 携 agent 上下文的用例已清零（现 60 处五工具引用全部绿）。
- 若将来实施"继承父 join"（Q1 另立）：新增用例 = 继承三态（父 joined→子放行/
  父未加入→子拒/父 cold-intent→唤醒后放行）+ 归因透传断言；夹具仅需
  `sessionNodes`/`joinedSessions` 种子注入，现有 `mount()` harness 已支持。
- 本提案范围内：**无**新增实施项、无 apply.spec 受影响清单需要出具。

### Q4 边界确认 —— **成立，且须三面分离**

| 面 | 辖区 | 门控 |
|---|---|---|
| 模型面工具（五工具） | 会话身份的工具调用 | **闸门辖区**（现网已实施） |
| 宿主进程服务 | 账本、receipt 回流、唤醒、marquee | **不得设门**——节点自身代谢，设门即切断 F2'/F5 结算闭环 |
| wire 协议 | `/a2a/direct` 无鉴权 POST | **F4 强制核心辖区**（与 F5 生债闸统筹，随 OriginClaim 兼容矩阵） |

提案把边界划在工具调用层：**正确**。宿主进程 team 直发不设门：**正确且必须**。
但"观察类工具保持宿主级"：**驳回**——teams/status/probe/tasks 泄露网络拓扑与
在场事实，放开即违背所有者预期边界；e4bc635 五工具全闸维持不变。

## 四、对提案文本的两处更正
