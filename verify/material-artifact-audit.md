# 发布物留存证据验证材料 v1

用途：发布后的留存包与验收证据核对，补齐 0.6.39 打包偏差的机器覆盖。旧 RC 材料和规格不改写；本规格不替代发布前 RC 判据、不新增人工门、不证明历史构建过程清洁或非自我评审身份。

## 判据

A1 发布物证据必须记录可读取 package.json 的完整候选提交 SHA 与有效打包时间。
A2 本地 tgz 实际大小、SHA-1 与 SHA-256 必须同时等于发布物记录。
A3 tgz 必须可枚举且文件数与记录一致，包内名称版本等于候选，且不得包含 pycache、pyc、临时目录或越界路径。
A4 3081 隔离验收记录必须绑定同一候选与实际 tgz 哈希，验收时间不早于打包，名片版本、隔离 state 与完整工作台 HTML 均通过。
A5 独立 serve 验收记录必须绑定同一候选与实际 tgz 哈希，验收时间不早于打包，名片版本、隔离 state 与完整工作台 HTML 均通过。
A6 npmjs 下载回读包的实际双哈希必须与本地验收 tgz 一致，记录的版本、大小及双哈希必须与下载包一致。
A7 Gitea 下载回读包的实际双哈希必须与本地验收 tgz 一致。

## 边界

采集器 scripts/verify-probe.mjs 的 --release-audit 模式读取实际包、git 候选对象及留存 JSON，写只含事实的独立快照。最终判定只认 ygl-trees verify run。缺失、损坏、版本/哈希/时间矛盾必须形成失败事实；不能因文件少了而跳过。

验收 JSON 是当时 HTTP 观察的记录，当前核对不重新启动历史服务，也不把记录身份当作密码学来源证明。candidate_identity 只证 SHA 对象和时间形状，不能从 tgz 反推出历史 HEAD 或实际干净构建。结构上相同版本但不同提交的编译代码仍需独立的构建血统核对，不冒充覆盖。

反例要求：篡改包/哈希；加入 pycache/pyc；丢失或换候选/版本/HTML/state；验收早于打包；两端下载字节不同；空证据目录。应分别 FAIL，不得空洞 PASS。
