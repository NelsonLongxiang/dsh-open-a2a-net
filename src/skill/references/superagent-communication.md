# SuperAgent 总工通信分流

本页供总工理解通道、维护者接入预设、运维核对配置。它不增加工具或权限，不授权建链、登记成员、批准外联或直接调用 HTTP。先分清“对方是谁、属于谁、来信是什么”，再选通道；“远程节点”只是位置，不是成员身份。

本页的总工专指 `superagent-router` 角色预设；[通用跨项目协调总工](router.md)是另一种身份，不能把它的普通 A2A 派发流程硬套进 SuperAgent 团队。具体角色以当前宿主登记、预设和实际工具为准。

## 总工先作四路判断

| 当前场景 | 总工应做什么 | 主机实际走什么 | 不要混用 |
|---|---|---|---|
| 外部普通节点/普通画布团队向本团队提需求 | 只对宿主给出的 candidate 按接单规则 accept / attach / ignore；已接工单的事实走 note，结果/提问走 reply | 请求方使用普通 A2A 到本团队的画布地址；本团队 Source、准入和 Policy 决定如何进入工单 | 收到 A2A 不等于属主授权；发送方不在名单或规则不匹配不能由总工自行放行 |
| 同团队成员在另一台主机或另一 DSH 实例 | 从当前候选/可读工单和有效成员池选择本团队成员；已有工单只按允许状态跟进或改派 | 主机代为派发；DSH 远程成员经签名成员接口收卡、经团队接口回报 | 不用 a2a_route、出站审批卡或普通 A2A receipt 管理团队内成员工作 |
| 工单需要本团队之外的团队或普通节点帮助 | 用 a2a_outbound_request 绑定工单、目标地址、精确正文和原因，等待审批与发送事实 | 出站 P0 卡获批后，主机以团队身份发普通 A2A；可信正式回执关联回原工单为 note | 地址可达不等于可派工；批准不等于已送达、接单或完成；总工不自批 |
| 本团队是根团队，对方是已登记子团队 | 只从宿主列出的子团队中选择 member；允许改派时用 superagent_assign | 主机派发 A2A，请求/回执与根工单关联；子团队自行接单和分配成员 | 不是普通远程成员；不能把子团队总工会话拉来充当根团队成员；登记以外的目标仍走出站申请 |

总工使用实际可见工具及其返回状态，不从地址形状、同 zone、同机、同一模型或显示名推断成员、子团队或授权。配置未知时说明具体缺口，提出由属主核对的最小动作；不要先发送探针来替代身份核实。

## 1. 同团队 DSH 远程成员：内部执行与汇报

同团队成员可以在另一台物理机，也可以在本机另一个 DSH 实例。位置变化不改变其工单角色：总工决定接不接、交给谁，不直接给成员会话发消息。

- 团队端的画布必须登记远程会话及所属主机，成员端属主必须用 serve 登记为该团队服务；双方钉住对端主机公钥。只添加 peer、同 zone 或一方能看到对方并不足以代替双方登记。
- 主机把 assign / input / stop 发到成员主机的 `/a2a/superagent-member`；成员仍调用 a2a_ticket_report 等团队工具，成员主机把汇报、确认、交回与回合事实签名送到 `/a2a/superagent-team`。这些路径是实现识别信息，不是让总工自行请求它们。
- 这段成员执行链不创建普通 a2a_route 任务、A2A 台账债务或正式 A2A receipt。外部请求进入团队时的 A2A 任务及最终回执是另一层，由 Source/主机管理。
- 总工用 superagent_read 读取当前候选/工单/决策；superagent_status 仅向已结束回合而未汇报的闲置工单执行者请求状态，不是通用网络健康探测器。成员已离开或报告无法继续等可改派状态，才使用 superagent_assign；新事实用 superagent_note，不以 note 扩大任务范围。
- 成员侧预设错误、未 serve、来源公钥不符或地址缺失，都可能阻止工作。由属主/运维核对，不由总工自行改 preset、加入别队、放宽 scope 或绕过角色守卫。

配置详情见 [Members on other hosts](superagent.md#members-on-other-hosts)。Pi CLI 席位是另一种成员平台，不能把它的信箱投递与 DSH 远程会话 HTTP 接口互换；见 [CLI 席位说明](cli.md)。

## 2. 普通节点/普通画布团队：外部请求方

普通画布团队是路由组，不自动拥有 SuperAgent 的接单/派单引擎。普通节点可以在有授权和准入的前提下，向本团队画布地址提需求；它并不因此成为本团队执行成员。绑定 SuperAgent 的画布地址先进入团队邮箱/引擎，不直接投递到总工或成员会话。

- 普通 A2A 的发现、路由和回执由 [setup](setup.md)、[membership](membership.md)、[routing](routing.md) 描述。发起方资格、目标准入和实际版本分别核对；发起人豁免不是接收方必接或跨团队的任意权限。
- A2A 来信是 agent 输入，不是人的同意。总工只处理宿主递交的 candidate，按 enabled rules 和 accept mode 判断；observe 下“本会接下”不是实际开单。未列发送方可能需要属主的 sender 决策卡；总工不能自己加白名单。
- 来信、delivered、acknowledged、progress 和正式结果互不等价。ack/receipt 的生成和关联由 Source/主机管理，成员报告不是发给外部请求方的普通 A2A receipt。

接入与确认细节见 [The A2A Source](superagent.md#the-a2a-source-agents)。这份源码资料不能证明某个运行实例已经开启来源、登记调用方或通过接单规则。

## 3. 向别队或普通节点求助：受控出站

已有开放工单才提出 a2a_outbound_request；传 ticket_id、address、text、why。地址可以是受支持的会话句柄或画布地址，不要求目标本身必须是 SuperAgent 团队。

- 总工可为本团队开放工单申请；成员/观察者只为自己持有的工单申请。
- P0 卡由属主，或属主指定的本地成员/观察者审批员决定。总工不因此成为审批员，申请人不能自批自己的卡。
- 只发送卡上的精确正文及受控团队/工单标题头，不自动附带整个工单、其他对话或凭据。批准只为该次精确目标提供发送范围，仍须通过接收方准入和接单规则。
- 发送失败和对方可信正式回执会成为原工单 note。读到回执也要读其结果，不能一律理解为 completed；普通后续消息与正式回执不是同一信号。

完整流程见 [Asking another team](superagent.md#asking-another-team)。不是根—子团队登记的目标，不能冒用根团队派工绕过出站卡。

## 4. 根团队与已登记子团队：对团队派工

只在当前宿主配置为根团队、且对方是已登记子团队时使用这一支。总工从候选卡的实际可选子团队中选 member，主机负责发送与回执映射。对子团队的正常派工不逐条再申请出站 P0 卡，登记关系就是该范围的持续授权；对其他目标仍走出站申请。

子团队仍按自己的准入、bot 名单、规则和接单模式决定是否工作。跨主机需要双边登记和回程链路；未登记、未接纳、等待答复或回执失败不能说成已开工。ack、progress、attention、result 由主机关联到根工单；停止和改派仍按工具状态与人的授权处理，不由总工手发控制消息。

配置与阶段边界见 [Root teams](superagent.md#root-teams-in-progress)。旧设计或源码存在不证明现场能力已启用。

## 最小反例：避免选错通道

| 情形 | 正确判断 | 应拒绝的替代动作 |
|---|---|---|
| 本团队有效远程成员等派单 | 正常团队工单分配，主机走成员执行链 | 再建一条外联 P0 请求或给成员 a2a_route |
| 一台普通节点只是已建链 peer | 它是外部请求方/目标，未证明是工人 | 直接作为本团队 member 派工 |
| 工单需要未登记的财务团队意见 | 对开放工单申请受控出站 | 把对方临时当子团队绕过审批 |
| 根团队选择已登记子团队 | 按子团队条目派工，主机关联工单 | 将子团队总工加入另一个团队或逐次索要同一出站批准 |
| 对方只回 delivered 或 acknowledged | 记录对应状态，继续由原任务对账 | 宣称完成或换任务 id 盲重发 |
| 技能要求 read/skill，但角色不允许 | 仅用当前已提供资料与获准工具；缺判据时报告具体缺口 | 偷用 shell、HTTP、其他会话或插件配置取资料 |

## 预设接入：核心内联，细节按需读取

总工默认 ROUTER_TOOLS 不包含 read 或 skill；额外授权可能改变实际可读工具，但不能假定每位总工都能加载本参考。因此核心四路分流已直接内联到总工模型提示词，不依赖运行时读取本页，不增加工具白名单。

唯一编辑来源是 src/superagent/prompts/router.md；模板 src/superagent/presets.patch.yml 只替换该角色的 persona prefix，其他角色和所有插件/权限保持基线字节。使用 pnpm build:presets 生成安装补丁，pnpm verify:presets 检查漂移；verify:core 在 build 之前先检查，不靠 build 静默掩盖未提交的变化。不要直接编辑生成文件。

工程回归核对生成输出、最终模型文本快照、四类通信判据、错误通道反例和默认角色守卫；这些是提示词/结构契约检查，不声称模型必然按规则执行。缺 read/skill 时不要求总工绕过角色取资料。

本仓源码集成不等于已安装包或现有会话已更新。应按项目现有发布、评审与安装流程分发，在新会话核对目标预设修订；本改动不修改运行 profile、已安装包、成员登记或主机配置，不部署、不合并、不放宽权限。
