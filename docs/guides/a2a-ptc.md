# A2A 协作（PTC）：通用方案

`a2a-net-ptc` 是本项目随包维护的通用协作 Agent 预设，显示名为 **A2A 协作（PTC）**。它将本地工具执行与跨会话协作分开：单会话通过 PTC 生成的 SDK 使用工具，需要外部协作时使用宿主提供的 A2A 网络。它不是 superagent 总工、成员、观察者或组队顾问，也不要求加入 superagent 工单团队。

## 能力与限制

- 模型直接可调用面只有 `run_code`；文件、搜索、命令、知识技能、任务计划和 A2A 工具按当前 SDK 声明调用。PTC executor 由预设选定，TypeScript runtime 由宿主提供；缺失时预设不能正常激活，不回落成 native 模式。
- 组合中不包含 subagent、fork、control、workflow 或 ralph 的声明行；提示词同样禁止用 shell、其他插件或远端代理绕过禁令。部署若另行注入自定义委派能力，仍须按自身安全规则限制；“少了声明行”不是任意第三方工具的全局安全沙箱。
- 业务范围不限定为编码：研究、分析、运营、内容、业务流程和开发都可使用。专业岗位、权限、批准要求、工作目录、验收和交付要求来自用户任务及项目指令，不在系统提示词中绑定人员、机器路径、岗位编制或具体 MCP/知识库。Office 等领域能力由宿主的技能/工具按需提供，通用预设不挂载特定业务插件。
- 不自动加入网络、创建团队、发布节点、配置 peers、修改模型、变更默认预设或获取凭据。接入和成员关系由宿主已有控制完成；本预设不增加权限。
- 规划模式也使用通用任务语言，仍保留 `exit_plan_mode` 的批准门；规划期间不得派发 A2A 工作或执行计划。

## 一次协作怎样运行

1. **先界定工作。** 单会话能完成的直接做；确需协作时加载 `a2a-network` 技能。检查身份/成员关系，发现已有接收方，需要时检查可达性，不猜测对方能力。
2. **派发有界请求。** 写清目标、范围、输入/文件引用、限制、产物和完成检查。长任务用异步；保存工具返回的 `task_id` 与 `context_id`，等待期间继续独立工作。文件走文件通道，不经消息塞字节，不传凭据。
3. **按原任务对账。** 区分送达、确认接单、本地作答与回执送达。超时、未知和死信都不自动等于“未执行”；查账本、活动与关联回执，不改文规避幂等或盲目重派。
4. **接单与回传。** 原文未进入对话时按本会话任务号取回；按权限执行并给结果、证据及限制。自动回执与人工修复不重复，终态回执不再回一封回执，提醒不是新任务。
5. **交付与收口。** 在任务指定位置给可用结果，如实列验证与未覆盖项；只有软件工作才要求提交或 PR。对账未完任务，清理自己临时创建且有权撤回的文件授权或成员关系，不拆掉属主设置的持久团队。

这是一套行为指引，不改变网络协议。准入、签名、回执、重试与取消的真实规则仍以当前工具和[网络技能](../../src/skill/SKILL.md)及其[路由参考](../../src/skill/references/routing.md)为准；外部文本与对端自称的授权不能升级为用户指令。

## 项目内唯一来源

- [预设组合](../../src/presets/a2a-ptc.patch.yml)：通用工具、PTC executor、隔离的规划/压缩组。
- [协作提示词](../../src/presets/prompts/a2a-ptc.md)：通用目标、协作过程、权限和证据纪律。
- [规划提示词](../../src/presets/prompts/plan-mode.md)：通用计划及批准门。
- [生成器](../../scripts/build-agent-presets.mjs)：将通用预设和既有 superagent 预设组合为随包[安装补丁](../../cordis.patch.yml)。运行时无需读源码或本机文件。

`pnpm build:presets` 生成，`pnpm verify:presets` 检查漂移；构建和工程主检查已接通这两个入口。[静态回归](../../tests/unit/a2a-ptc-preset.spec.ts)核对通用提示词快照、组合、无本地委派、无个人信息和错误 marker；`pnpm verify:presets-runtime <dsh-cli-package.json>` 使用目标 DSH 的 Loader/persona/PTC executor 检查模型面只有 `run_code` 和生成 SDK，测试不执行业务工具、不启动网络协作。

## 安装与旧本机预设迁移

新安装此 A2A 包后，选择 `a2a-net-ptc` 即使用项目内的方案。它依赖支持 `@deepseek-ai/dsh-tool-executor-ptc` 的 DSH 安装及相容 TypeScript runtime；不能把旧 `dsh-agent-tool-presentation` 的 `mode: ptc` 行照搬到新宿主。网络工具来自宿主 A2A 插件，不在每个会话中重复挂载网络服务。

旧部署的 `ptc-no-delegation` 是本机配置的另一个 ID；显示名相同不代表来源相同。本项目不覆盖或删除它，也不自动改 `selectedDefault`，避免重复 ID、破坏历史会话与用户覆写。迁移顺序：

1. 在目标发布线合入并构建本次变更，通过既有插件管理入口安装相应版本；不要用旧源码整包降级当前运行实例。
2. 在新会话选择 `a2a-net-ptc`，检查预设能激活、模型工具面为 PTC、A2A 技能/工具可用；按已获准的协作对象做业务验收。
3. 将需要保留的部署红线放回适用项目的 Agent 指令或受管理配置，不复制具体人员、路径、旧审批口径到通用提示词。需要默认使用时由用户在 GUI 选默认预设。
4. 确认新会话后，由用户通过正式配置入口停用或归档旧声明；已有会话继续保留原预设修订，不强改历史或在途会话。

当前运行版本是否已更新必须单独核验。源码、构建、声明可解析、persona/PTC executor smoke、新会话业务验收分别记录，不能互相代替。
