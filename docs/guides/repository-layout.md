# 仓库目录与产物归位

本文件规定本仓库的目录职责。治理采用保全和可逆迁移，不因文件“看起来旧”就删除，不把 Git ignore 当作保密、备份或自动清理机制。

## 根目录保留什么

根目录只保留包与工具链发现所必需的入口：README（中英）、LICENSE、THIRD_PARTY_NOTICES、AGENTS、package.json、pnpm 锁与 workspace、TypeScript/Vitest/tsdown 配置、cordis.patch.yml、Git 配置文件。不要为了减少文件数搬走这些入口，否则会破坏安装、构建、许可证或宿主发现。

| 位置 | 职责 | Git |
|---|---|---|
| src/、cli/、pi/ | 正式运行代码、CLI 和随包扩展 | 跟踪 |
| scripts/ | 项目级维护、检查和构建的唯一正式入口；跨任务复用的工具先补测试再晋升到这里 | 跟踪 |
| tests/ | 用例、夹具和测试辅助 | 跟踪 |
| docs/ | 正式规范、契约、设计和运维记录，分别进入既有子目录 | 跟踪 |
| assets/、images/ | 产品使用的资源与受门禁约束的前端产物 | 按现有构建契约跟踪 |
| examples/ | 可复用示例 | 跟踪 |
| verify/ | 冻结验证材料和判据 | 保持现有跟踪规则，不回写冻结材料 |
| tmp/<任务标识>/ | 一次性脚本、试验、构建审计包、日志及可控测试临时数据 | 忽略 |
| feedback/ | 本机研究、反馈、截图与原始评议，不是正式规范或交付唯一入口 | 忽略，保留本机文件 |
| a2a-inbox/ | 收件工具管理的文件，原引用可能依赖该路径 | 忽略，不自行搬走在途收件 |
| lib/、node_modules/、coverage/ | 构建输出、依赖和覆盖率缓存 | 忽略 |

正式文档不可依赖只在本机存在的 feedback/tmp/inbox 文件。已采纳结论应保留在正式契约中；历史依据链接到固定提交的原文件，不能使用浮动分支，也不复制整套私人反馈进文档树。

## 写入与整理

1. 写入前先找已有正式对象，确认任务归属、用途和消费者；一次性工作进入本项目 tmp/<任务标识>/，不要落在根目录或系统临时区。
2. 新的 tgz、解包 package/、日志和补丁脚本放到任务目录；根目录只使用 pnpm-lock.yaml，子项目 nexus-stage/package-lock.json 继续跟踪，不要用全局 package-lock.json 忽略模式误伤它。
3. 取消 feedback 跟踪不等于删除本机数据。执行者使用索引级取消跟踪，先确认暂存区没有他人在途改动；保留文件并校验。其他检出在采纳这次提交前，也应先保全自己的本机修改；不要盲目 restore/reset/clean。
4. 归档先查活度、引用、属权和唯一性，记录原路径与任务目录中的目标路径；逐文件核对后做同批对账。不得覆盖已有交付或他人修改，不移动锁文件、运行态和凭据。
5. 任务证据按实际引用保留，不自动清空 tmp，不按年龄删除。Git 历史记录原先跟踪的 feedback；ignore 只阻止新增误提交，不抹掉历史。

## 检查入口

- pnpm verify:layout：运行布局正反例，再只读检查 Git 索引与真实根目录。会识别被跟踪的本地资料、根目录未归位产物；不因为文件被忽略就把实际散落隐藏起来，也不会执行删除。
- pnpm verify：复用现有临时目录生命周期入口，在项目 tmp/ 下分配本次测试的独占目录；通过子进程正式环境让 tmpdir()、测试 ygl 工作区及子进程使用该目录，检查残留后只清理本次拥有的目录。无需改全局 TMP/TEMP。直接 pnpm test 不具备该临时根保证，需遵循本任务环境约束选用入口。
- 目录检查不能替代类型、构建、业务测试、冻结 spec run 或运维验收；结果及未覆盖项分别记录。新增顶层入口须连同布局策略、文档及回归一起更新，不靠扩大 ignore 隐藏问题。
