# 舰队治理手册（席位 SOP · 派单环 · 双章 · 合并治理）

> 来源：`dsh-agent-skills/a2a-supervisor-sop` 技能整编（2026-10-23，随 network-operations.md 一并入库；CLI 章节已退役）。
> 面向：监督席、代决策席、评审/测试席位。操作面（入网/路由/故障）见 `network-operations.md`。

## 一、角色铁律（先读）

1. **监督席只调度不实现**：实现交属地席，评审独立，作者不自合（零例外）。
2. **属地分治**：每席守本机；跨机操作经属地席或授权链。
3. **主人专属门**：生产宿主重启与 profile 变更归主人；监督线只做准备与暂存。
4. **权内自裁，权外排讨论**（属主准则 2026-10-23）：席位裁决权内自裁；无法裁决的排讨论（三席证据面），汇总成决策备忘呈属主——不悬置不越权。

## 二、席位接管（新席上任标准动作）

1. 读交接文档，吸收铁律与在途线清单。
2. 三查：`a2a_status`（peers/活动环/幂等窗）+ `a2a_teams`（目录+活动事实）+ `a2a_tasks`（欠回执台账）。
3. 看板对账：in_review/in_progress/todo 逐层扫，与交接清单比对。
4. 输出接管报告（状态+关键数字+证据路径），候属主首批裁定。

## 三、派单环（看板驱动）

1. 节奏环四步：全状态扫描 → 无主卡批量派发（附「认领前读卡核现状」）→ 收割回执即处理 → in_review 候验收。审计先行，零重复交付。
2. 派单前三查：目录在册 / 目标 host live+joined / 单通道（同对象唯一催收方）。
3. **API 核 PR 作者字段**（跨席转报不得从消息上下文推断——「作者本席」误读事故在案）。
4. 任务书六要素＋按仓惯例定制铁律（措辞歧义会逼执行席违规或空转）。
5. 前置断言两件套（合并令类）：作者核查＋PR 状态核查（open+mergeable）。
6. 派发后：回执协议（直达/三选一/ETA）＋台账登记＋催办时钟=最近实质回执。

## 四、双章流程（评审 × 测试）

1. **三线分离**：作者 ≠ 评审 ≠ 测试，三个不同节点。
2. 评审章：派单（评审点+对抗性要求）→ 受理 → 取证 → 逐点结论（PASS/FAIL/WARN）→ GitHub/Gitee 面落章（`gh pr review` / `POST /pulls/{n}/review`；reviews 复数端点 404，comments=0≠未评审）。
3. 测试章：worktree 独立复跑（门禁+行为定向+安装面）→ 逐面计数回执 → 环境即清。
4. FAIL 退回：结论+方案级修复要求 → 作者修 → 复章（一轮门禁）。
5. **GIF 闸**（GUI 可见变更）：真实服务器实录/几何目验 + 四字段凭单 + 闸门对象本人放行——座席视觉核验只是 QA 不闭环。
6. **章务回执必须正式落账到监督席**（转述≠落账；作者转述他席 PASS 不算——两次定式在案）。

### 对抗性评审纪律（本仓实证沉淀）

- 评审者给的修法也可能是错的：开发席实证评审席处方（如信封取卡互递归）与评审席实证开发席实现（如单 zone 冒充/basis 播种）都对——**对抗探针真跑 > 推演**，每轮复章重跑探针。
- **测试拓扑必须含部署形态**（单 zone/同宿多会话）——异 zone 测试舰队测不出现实（两轮同课在案）。
- 验收条不过=不过：FAIL 与 PASS 都是产物，证据链是唯一裁判。

## 五、合并治理

1. 合并令前置：双章齐（回执落账本席）＋监督席合并令＋非作者执槌。零例外。
2. 默认 `--no-ff`（merge commit 留第二父=审计可追溯）；偏离形态主动如实披露，按「内容零损＋审计替代」判定。
3. **合并锁**：落闸权归单一道，先落闸者有效，后到令作废（racing 实证在案）。
4. 四件套回执核验：merge SHA / state=merged / merged_at / head∈origin-master（`merge-base --is-ancestor` 双验+`ls-remote` 对账+与双章门禁数字互证）。
5. 越令/缺陷合并处置：遏制（revert -m 1）→ 事故报告三问 → 定性 → 执槌权处置 → 受控 re-land（revert→修复头新 PR→原 FAIL 席双复章→监督令）。
6. 孤儿提交拦截：向已 merged PR 分支追加增量=孤儿——先读 PR state，merged 即退回开新 PR。

## 六、台账对账与催办

1. `a2a_tasks` 只读收割：新鲜回执（<30m）即处理；历史 pending 不计静默。
2. 催办四级阶梯：轻推 → 进度三选一 → 正式催办附窗口+改派预告 → 终态二选一。单通道，死节点不重复注入。
3. 回执缺失三判别：会话自然冷 / registry 归档误报 / 进程收割。
4. 兜底：`context_id` 续聊催收；看板持久通道（目标不可达时）。

## 七、事故处置五步

勘察（只读多面同时刻对账）→ 定性（证据链闭合才定性；归因错误即改）→ 遏制（revert/停权/HOLD，机械可逆优先）→ 修复派单（正式流程不降格）→ 复盘入档（Scar+流程卡+memory attune）。

## 八、升级与协调

1. 代决策席对表：例行 ping 三问式回执；扩权期可直报证据齐的非重启阻塞项。
2. 权限边界：生产重启与 profile 变更=主人专属门。
3. 移交接管：执行席亲请+原协调席积压实据=显式移交合法；移交知会必发原协调席（防双派）。
4. 紧急缓解：主人直令+即时披露三要素齐=追认；先报后动为上。

## 九、沉淀纪律

1. T+0 固证：证据双置+MANIFEST.sha256 封存。
2. 裁决内含边界硬约束与反悔条件；执行线按约束停手=记功；前提崩塌裁定自动失效回门。
3. 三源合一沉淀 → 聚合卡登记 → 本体 intake。
4. 看板评论=证据主通道；两跳登记（todo→in_progress→in_review）；done 永远主人。
