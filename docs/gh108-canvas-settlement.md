# #108 画布写入与布局结算修复

## 观测与未证实的部分

历史观测（2026-10-30 .157）只有：布局中有目标框几何、当次 state 的本机
canvas 团队列表没有对应团队、用户说界面可见该框。它不足以证明团队
“从未落库”、用户未保存、全网不存在、一定是乐观框，或旧版本无回滚。
有限活动环里没找到事件也不能证明没有事件。前次归因过度，此处纠正。

## 可重复复现的代码缺陷及修复

1. canvas-wire 将 HTTP 200 的 error-less ok:false 一律作成功，但服务端
   CanvasStore 在队/成员达到上限时也返回该形态。前端因此不回滚且继续
   后续操作。修复：正向动作必须显式 ok:true，或返回成员列表证明目标
   已存在；删除/离队可由返回列表证明目标已不存在，保留真实幂等。
   其余未确认/空/畸形响应显示失败，不再误报加入成功。
   独立复核发现：客户端created=true不证明服务端本次新建，首成员容量
   拒收后的无条件remove会删已有同名满员队。现彻底取消补偿删队：
   保留服务端已有队/成员（或真正新建的空队）供重试，不新增删除接口。
2. emitAction 在失败回滚与散队结算后不标脏布局。若旧的乐观布局已发出，
   后续无纠正保存；layoutDoc 中被删团队的几何还会被同名新队重用。
   修复：结算/回滚后沿既有 saveLoop 标脏，已删除新建队或成功解散队
   的本地 adopted layout 缓存只删其自身键；删队被拒则恢复原几何。

不进行“把当前看不到的框全部删掉”的清理：离线对端/远端框可能不在
这一轮 inventory，位置必须保留。无历史数据迁移、无自动散队。
未解决跨标签/跨客户端旧 POST 写回冲突，这不冒充事务式服务端清理。
