# 设计：做减法（2026-11）——canvas 按名可达、一条链接规则、清旋钮

状态：草案，待属主裁定 D1、D2。作者：评审席。跟踪 issue 见文末。

## 0. 一句话

属主 2026-11-04：「去中心化网络不应该要调用方指定 host」。今天线上的问题几乎都出在规则叠加上，而不是缺功能。本稿只做减法：让常见路径不需要任何人知道主机，把多条链接规则收成一条，并在过渡期结束后删掉开关。签名与授权链的校验强度一条都不降。

## 1. 现状与证据（master c04297a，0.6.38）

- **按名路由要先知道主机**。canvas 名只在属主主机上解析；跨主机靠 #57 的一跳转发。同名 canvas 在多台主机上合法存在（.156 与 .156:12080 各有一个「dsh-ecom-prodcut-dev--开发组」），#276 只能列候选、拒绝猜。
- **转发到 canvas 需要 N+2 条链接**（`docs/design/cross-host-forward.md` §2.3、§2.4 F3 结论）：
  1. H2 的运营者把 CLI 句柄加进 H2 的画布队；
  2. 链接时恰好一台已链接主机列出该句柄，才自动钉住 home；
  3. H 的运营者必须**直接链接 canvas 的每一个接收成员**，否则回执回程被拒，发送前就跳过这个候选。

  属主 11-04 在「多平台部门」上实测：要在 .156 上逐个拖 5 个 .43 的成员，其中一个还是 .156 本机会话。
- **旋钮**：与签名、转发、结算有关的就有 `originClaimWindow`、`originClaimUnboundWindow`、`originClaimAudiences`、`originClaimUrl`、`forwardDirect`、`settlementAuth`、`teamScopeRouting`、`teamScopeInfo`、`targetQueueCap`。其中前两个和 `settlementAuth: observe` 都是过渡态。
- **线上事故**（11-04 一天）：排队名额被已回应的行占满（#253）；转发行不结清、canvas 成员回执判 off-chain（#272）；旧欠账挡 enforce 时插件起不来（#277→#278）；「已链接」徽章按 zone 判错（#269）。

## 2. 提案

### D1 canvas 用带属主的全局 id 路由（需属主裁定格式）

- canvas 的路由键由 `<zone>/canvas/<name>` 改为 `(属主名片公钥, name)`，文本形式 `<zone>/canvas/<name>@<属主公钥指纹前 8 位>`。
- `<zone>/canvas/<name>` 继续可用：当可见目录（本机加 peerOrg，#276）里恰好一个属主时直接解析；多个时拒绝并列出带 `@指纹` 的候选（与今天一致，但给出可直接复制的 id）。
- `teams`、`whoami`、画布框头都显示带 `@指纹` 的 id；显示名可以重复，路由不歧义。
- 指纹取自已验签的名片公钥，不取 URL：主机换地址（LAN↔Tailscale）不改 id，伪造需要私钥。
- **不改**：会话句柄 `<zone>/<id8>` 的格式；签名信封；准入判据。

### D2 一条链接规则：「同队即授权」（高档，需属主裁定）

转发到 canvas 时，用 **canvas 属主签名的成员快照**代替「H 直接链接每个接收成员」：

- H 只需链接 **canvas 属主主机**（peer linked，双向种子）。今天要 N 条，改后 1 条。
- 回执校验沿用 #274 已有的机制：选中对端的 origin/key 必须匹配，结算人必须在**出生时冻结的、来自该对端已验签名片的** `receiverMembers` 里。也就是说，回程信任锚是属主主机的签名，不再额外要求 H 的运营者逐个背书成员。
- H2 侧不变：CLI 句柄仍须由 H2 运营者加进该 canvas（成员即授权），home 仍按链接时钉住。改进一处：在属主主机上把 CLI 句柄加进 canvas 时，如果 CLI 的 home 已在 H2 的已链接主机里且唯一，就自动钉住；不唯一时 UI 要求选一台，而不是静默不钉。
- **安全论证**：今天「H 直接链接每个成员」防的是「对端主机谎报成员」。D2 下，谎报成员的只能是 canvas 属主主机本身，而它本来就是这个 canvas 成员关系的权威来源，H 已经选择信任它（链接了它）。对其他主机的谎报，D2 与今天一样拒绝：key 绑定、快照冻结。
- **不做**：不放宽 H2 的准入；不允许非成员发到 canvas；不去掉 key 绑定。

### D3 过渡期结束后删开关（中档，按条件逐个）

| 开关 | 删除条件（机器判定） | 删后行为 |
|---|---|---|
| `originClaimUnboundWindow` | #64：全舰队 `unboundInbound`、`boundMissInbound` 连续 7 天零增量 | 只验绑定形式（Sig2/Sig3） |
| `originClaimWindow` | 同上，且 `legacyInbound` 连续 7 天为 0 | 无信封即拒 |
| Sig2 单独形式（只对带 body 的请求） | 全舰队 ≥ 0.6.37 且 market 已切严格模式 | 带 body 的请求只认 Sig3，堵住「剥掉 Sig3」的降级 |
| `settlementAuth: observe` | #125：L10/L13 连续 7 天为绿、`enforceBlockers` 为空、全舰队升级 | 默认 enforce；保留 `observe` 作为应急值但不再是默认 |

目标：签名、转发、结算这一族的配置项从 9 个降到 5 个（`originClaimAudiences`、`originClaimUrl`、`forwardDirect`、`teamScope*` 合并为一项、`targetQueueCap`），文档里的「过渡期」字样清零。

### D4 每个拒绝只给一个原因和一个下一步（中档）

- 路由、转发、准入、结算的拒绝统一为 `{ code, reason, next }`。`next` 是一句可执行的话，例如「请 10.20.30.15 的属主把 apps-page-seat/03fb31a2 加进多平台部门」。
- CLI 只打印 `reason` 和 `next`；完整诊断放在 `--json`。
- 用例覆盖今天出现过的每一种拒绝。

## 3. 不做的事

- 不降低任何签名、授权链、key 绑定的校验强度。
- 不做 P2P 穿透或中继（长期方向另议）。
- 不改会话句柄格式。
- 不自动链接主机：链接仍是运营者的动作，D2 只把次数从 N 降到 1。
