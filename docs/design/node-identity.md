## 0. 一句话

今天，**节点就是会话**：会话没了，身份、职责和积累的经验也跟着消失。本设计把身份、任务状态和分层的系统提示词挂到一个由人起名、长期存在的**节点**上，会话退化为节点的执行载体。

节点可以按规则更新自己提示词中的可变层。每次更新都冻结为一个版本，新版本**从下一个会话起生效**。版本可以归因，也可以回退。

## 2. 节点存储

位置：插件自有存储 `<DSH home>/a2a/nodes.json`，与 peers.json 和 canvas.json 同级，写法沿用现有 Store 的模式。

提示词版本单独存放，**分两个命名空间**，都只增不改：
- `<DSH home>/a2a/nodes/<name>/core-v<n>.json`：不可变层；
- `<DSH home>/a2a/nodes/<name>/mutable-v<n>.json`：可变层。

```jsonc
{
  "name": "review-1",               // 稳定节点名：人设定，不可改名（见下）
  "label": "评审席",                 // 展示名：人可改，不参与路由
  "role": ["review"],               // 职责：dev | review | supervise | ops | intake …
  "teams": ["dsh/canvas/core"],     // 投影；成员关系以 canvas.json 为准
  "carrier": {                      // 新建会话所需（经会话控制器）
    "cwd": "/path/to/checkout",
    "agentPreset": "<preset id>",
    "model": "<model selection>"
  },
  "prompt": { "core_version": 3, "core_sha256": "…", "mutable_version": 17, "mutable_sha256": "…" },  // 两层各带 sha，供 CAS
  "tasks": [                        // 任务指针：只记编号与状态（N6 加入，N1 尚无）
    { "ref": "NelsonLongxiang/dsh-open-a2a-net#160", "state": "open", "since": "…", "core_version": 3, "mutable_version": 17 }
  ],
  "sessions": ["<session id>"],     // 会话绑定（N2+N3 加入，N1 尚无）
  "created_by": "human:<who>",
  "created_at": "…"
}
```

- **命名**：由人通过管理面创建，**不可改名**（r1 允许改名，但没定义旧句柄、画布成员引用和台账行怎么办，所以收窄为不改名）。要换名就新建节点，旧节点归档；`label` 可以随时改。节点名永不复用。
- **身份类写入的强制级别**（name / role / teams / carrier / 不可变层 / 回退）：**写入必须带 apiKey，回环地址也不例外**，不走模型可调用的任何工具（§8-2 已拍板）。
- **版本链**：
  - 新版本号 = 该命名空间里现存的最大版本号 + 1，回退之后再写也不会撞号；
  - 每个版本存**整层全量快照**（可变层不到 3000 字符），不存增量；
  - `sha256` 覆盖规范化 JSON 的 `{version, sections}`；
  - 写入带 CAS：调用方给出 `expected_sha256`，与当前值不一致就拒绝，以防多个并行会话同时写。
- **单进程**：一个 DSH home 只由一个宿主进程写。CAS 比对的是进程内的名册，多个进程共用同一个 home 会丢失名册更新（版本文件靠 `wx` 加 max+1 不会撞号，但名册指针会分叉）。不支持这种部署。
- **损坏处理（N1 #164 最终实现）**：
  - 名册读不出，或读出来不是名册的形状（`null`、数组、`nodes`/`retired` 不是数组）时，**复制**一份为 `nodes.json.corrupt-<ts>`，**原文件留在原处不动**。只要它仍读不出，每次重启都保持只读，身份写入返回 503，绝不覆盖读不出的文件。
  - 格式坏的单条记录被丢弃前，先把原名册备份为 `nodes.json.dropped-<ts>`，被丢弃的名字转入 `retired`。
  - `create` 时先建节点的版本目录，再写名册。节点名只要有版本目录就视为用过，丢了名册也不会被复用；没写过任何层的节点也一样。
- **任务指针**：状态取值为 `open` / `merged` / `closed` / `declined`，以 GitHub 为准，这里只是缓存（核对机制见 §6）。只保留最近 64 条，更早的转存到 `tasks-archive`。
  - 实现说明（N6）：指针存在 a2a home 下单独的 `node-tasks.json` 里，不放进名册记录。原因是这份缓存每次核对都会变，不能因此重写身份名册。溢出的指针追加到 `node-tasks-archive.jsonl`。核对之前状态是 `unknown`；核对答不上来时，保留上次已知的状态，并标为「未能核对」。管理面用 `track` / `untrack` 两个动作（身份写入，带 apiKey）登记和移除指针，节点归档时它的指针一并转存。

## 3. 会话与节点的绑定

- **前提是已 join**：只有已 join 的会话才能绑定节点。这样不违反裁定 B（未 join 的会话不可见），路由看到的是 `sessionNodes`（`src/index.ts:1445-1450`）。
- **发起方**：由人在工作台发起；或由投递路径（§4）经会话控制器新建会话时直接带上。
- **绑定即生效**：绑定时立即在该会话的 `agent.ctx` 上注册提示词段（§5）和 `node_update_self` 工具，并保存 disposer。解绑时 dispose。
  - 工具集中途变化会付出一次缓存代价（§1），这次代价可以接受，在工作台上提示。
- **补注册**：插件加载时，遍历已存在的 roots，为已绑定的会话补注册（参照 `src/index.ts:1679`）。
- **`agent/created`**：不看 `source`，无条件按绑定表注册，覆盖 startup、resume、clear 和 compact。整个监听器包 try/catch：nodes.json 损坏时只记日志、不注册，不能否决会话发布。
- **结束的定义**：会话离开网络时绑定结束；会话归档后绑定**失效**（不再挂载、不能新绑），但绑定行保留（见下面的实现说明）。冷却卸载（`agent/disposed`）不算结束，绑定保留，这样之后还能续上。
  - 实现（N2+N3）：离开网络（leave，或 join 意图被 JOIN_CAP 挤出）时删除绑定、撤掉节点段；节点归档时同样。已归档的会话不挂载、不能绑定；它若仍在运行，节点段在归档清理时撤下。绑定行保留，和 join 意图一样（3081 教训：归档状态的读数可能短暂出错，不能因此毁掉持久意图）。清理只按差集做：只结束「上次读数里在、这次不在」的会话的绑定。joined.json 解析失败会读成空表，不能据此删光绑定，启动时和之后的第一次 join/leave 都一样。行数受 JOIN_CAP 约束。可变层的围栏标记和行首 `#` 在渲染时转义，节点自记不能跳出围栏、也不能伪造标题。
- **约束**：一个会话最多绑定一个节点；一个节点可以同时有多个活会话。

## 4. 名片、准入与投递

### 4.1 名片

- **节点以不签名、读时生成的行发布**，做法与 `sessionTeams`、CLI 户口相同：路由名 `<zone>/node/<name>`，附带 `{role, teams}`。
  - 这样旧对端不用升级验签器，经 `directoryPeerCandidates`（`src/index.ts:4323`）就能看到并路由到节点。
  - r1 推荐把 `nodes` 放进签名载荷，会让旧对端整张拒收名片，已撤回。
- 要签名，就分两段走：先让全舰队升级验签器，再开始签名。签名另案处理，届时再请属主拍板（§8-3 已定本期不签名）。
- `live`（是否有活会话）只出现在 full card，不进最小名片（§8-3）。
- 过渡期，绑定了节点的会话仍以 `<zone>/<id8>` 出现。

### 4.2 准入

**节点有显式分支，不落进主机级放行。** 在 `sameZoneAdmission` 把目标当成 id8 之前，先识别 `<zone>/node/<name>`：
- 用节点所属的画布队计算 `targetLinks`；
- 节点不属于任何画布队时拒绝（`-32000`，理由为 node has no team）；
- **绝不**退回 `pass(routable ∪ otherLocalDeclarations)`。

节点与会话的绑定、节点与画布队的关系，都进入 `AllowlistInputs`（114 §2.3）。改绑之后 `allowlist_version` 随之变化，S6 重判不会漏掉。这会改动版本哈希的黄金向量，需要单独一个提交，并附反例：改绑前后版本不同。

### 4.3 同 zone 跨主机撞名

默认 zone 是 `dsh`，所以人起的名字在多台主机上可能相同。

- **路由只认名片里发布了这个节点的那一台主机。**
- 多台主机同时发布同一节点名时，**拒绝投递**，并在 `a2a_teams` 里显示冲突，不按 #131 的种子否决规则选一台。
- 本机已有同名节点时，对端发布的同名节点不得劫持本机路由：本机节点优先，同时记录冲突。

### 4.4 投递到节点

1. 这个节点有活会话：沿用今天的 `followup` 或 `steer`；
2. 没有活会话但有可续的会话：`ctx.sessionController.resolveAgent(sessionId)`；
3. 都没有：`ctx.sessionController.create({ cwd, agentPreset })`，用 `carrier` 中的字段，建好后写入绑定。

**不直接调 `ctx.agents.create/resume`**。直接调会绕开控制器的模型选择、预设挂载和 agentOptions 组合，造出 Web 端不认识的会话，而且 handle 归插件所有，插件卸载时会被 dispose。提示词段统一由 §3 的 `agent/created` 路径注册，没有 setup 路径，也就不会出现同一作用域重复注册的问题。

### 4.5 回执

节点发起投递时，`callback` 填节点路由名 `<zone>/node/<name>`。这样即使发起的会话不在了，回执也能落到节点的任一活会话或可续的会话上。

调用方标签（`caller_session`）仍是会话团队名。`ZONE_ID8`（`src/task-auth.ts:87`）不接受节点形状的调用方；让节点自己当调用方另列一项，不在本稿范围内。

## 5. 提示词分层

| 部分 | 载体 | order | 内容 | 谁能改 | 生效 |
|---|---|---|---|---|---|
| 可变层 | section `a2a:node:mutable` | 10150 | 四段：**当前状态 / 执行要点 / 已知陷阱 / 当前重点**。用围栏包起来，并标注「节点自记，优先级低于下方的节点契约」 | 节点自己（§6），人也可以改 | 下一个会话 |
| 不可变层 | section `a2a:node:core` | 10180 | 身份（节点名、职责、团队）、先授权五类、项目红线、协作规范要点，并写明**本段优先于上方的节点自记** | 只有人（带 apiKey 的管理面） | 下一个会话 |
| 任务状态 | context `a2a:node:tasks`，`required: true` | runtime context | 任务指针清单、各自状态、最近一次事件 | 插件生成 | 即时，只追加 |

- **缓存的真实代价**：系统提示词一变，对 leading-only 线路就是「整段历史重新预填」，段排在哪里都一样（§1）。所以两个段的文本**在绑定或会话开始时冻结快照**，会话进行中不再变化。
  - 新版本从下一个会话起生效。
  - 节点在会话中途写了更新，本会话改用 runtime context 追加一条「本会话已记录的更新」，不改系统提示词。
  - r1 的论证是「段排在最后 → 前缀缓存损失最小」，这个说法不成立，已撤回。
- **order**：两个段都放在 10200 之前，`DEPLOYMENT_PERSONA_SUFFIX` 仍然是部署方的最后一句话。不可变层排在可变层之后，再加上显式的优先级声明，防止节点自记盖过红线。
  - 预设如果用 `complete` 整体替换提示词，节点段会被丢掉。这时在工作台给出提示，不强行注入。
- **不插值**：三部分一律 `interpolate: false`。可变层和事件里出现 `{{x}}` 之类的文本，也不能让组装失败。N3 带反例：可变层写入 `{{x}}`，组装仍然成功，且原样保留。
  - 插件热重载：绑定行记录每次挂载冻结的版本号；插件加载时，对已经在运行的会话按记录的版本号重新挂载，head 不变（#174）。记录的版本读不回来（文件缺失或损坏）时，退回当前版本。新会话（`agent/created`）一律取当前版本。
  - 实现说明（N2+N3）：现装的 system-prompt（0.1.0-rc.6）没有 `interpolate` 选项，遇到不认识的 `{{name}}` 会直接让组装失败。所以段文本只写一个变量引用 `{{a2a_node_core}}` / `{{a2a_node_mutable}}`，冻结的正文挂在会话作用域的同名变量上。库不会再扫描代入的值，`{{x}}` 因此原样保留（`tests/mesh/node-bind.spec.ts` ③）。
  - 任务状态 context 和 `node_update_self` 分别要等 N6 的任务指针和 N4 的审核队列，随这两片落地，N2+N3 不注册。
- **字数配额**（字符数）：
  - 不可变层 ≤ 2000：超出时写入被拒绝；
  - 可变层合计 ≤ 3000，每段 ≤ 1000：超出时写入被拒绝；
  - 任务状态 ≤ 1500：这部分是插件生成的，所以不是拒绝，而是**截断**。按状态（open 优先）和时间排序取前若干条，尾部写「另有 k 条，见 GitHub」。

## 6. 自我更新：`node_update_self`

- **工具**：只有绑定了节点的会话才注册（§3）。参数为 `{section: '当前状态'|'执行要点'|'已知陷阱'|'当前重点', text, reason, expected_sha256}`。工具没有写名字、职责、团队或不可变层的参数。
- **远端来源的轮次不能写**：本轮输入来自远端（任务授权记录的 `via` 不是 `host-face`）时，调用被拒绝，并转入人工审核队列，在工作台展示 diff，由人批准后落版本。
  - 这是为了堵住入站 A2A 内容诱导模型，把文字写成持久的系统级指令。
- **频率上限**：每节点每天最多 8 次（可配置），超出时拒绝。
- **每次写入**：
  1. 检查配额，再做 CAS；
  2. 写 `mutable-v<max+1>.json`，内容为 `{layer, version, sha256, parent_version, sections(全量), changed, reason, by, via, at, rollback_of?}`（N1 #164 的实际字段；`by` 对人工写入是 `human:<who>`，N4 起节点写入记会话）；
  3. 更新 nodes.json 的 `mutable_version` 和 `mutable_sha256`；
  4. 本会话以 runtime context 追加一条已记录的提示（§5）。
- **触发**：
  - 主触发是一件事结束（节点任务指针上的 issue 关闭或 PR 合并），由 GitHub 核对发现后，用 `followup` 提醒节点复盘；
  - 上限触发是累计 N 轮（`turn/end` 计数，默认 40）没有更新，提醒一次；
  - 提醒只是消息，更新与否由节点判断。
- **GitHub 核对**：
  - 凭证用主机环境里已有的 `gh` 登录或 `GITHUB_TOKEN`，插件自己不存凭证；
  - 时机：节点任务指针变化时核对一次，另外每天两次全量核对；
  - 没有凭证或离线时降级为「状态未知」，不触发提醒，在工作台标出。
- **归因**：每条任务指针记下开始时的 `core_version` 和 `mutable_version`。结果指标取 GitHub 事实：PR 是否合并、从开到合用了多久、评审往返几轮、是否回滚，按版本聚合。
- **回退**：人在带 apiKey 的管理面把 `mutable_version` 指回旧版本，回退本身也追加一条记录。节点没有回退工具。
- **实现说明（N4）**：
  - **属主裁定（2026-11-03）「会话级污染」**：§9 里的 `via != host-face` 解释为「本会话收到过来自本机以外的输入」。会话一旦被污染，它此后的每一次自我更新都进人工审核队列；标记持久化，永不清除。两路信号，任一命中即算污染：
    1. **投递时打标**：宿主把远端内容送进会话时，在会话上打标。所有 relay steer（投递、它的 nudge、取消通知）和 queue 模式的 nudge 都会打，记录在 `node-taint.json`。这个文件读不出时，所有会话一律按已污染处理（失败即关）。
    2. **日志兜底**：扫描会话的全部事件。出现以下任一情况即算污染：不是宿主生成的节点提醒的 `a2a-relay` 消息；controller rpcId 以 `a2a-` 开头的 `user` 消息（本插件发的 nudge）；本模块不认识的来源；整段日志里没有一条本人的输入。
    - **中性消息**：agent loop 自己注入的 runtime-context、time-context、skill-catalog、tool-jobs、user-approval 等既不算输入，也不算污染。
  - **边界**：模型通过自己的工具读到的远端文字（网页、issue 正文）不是投递，不会造成污染。
  - **审核队列**：存在 `node-review.json`。
    - **容量**：全局最多 64 条，每个节点最多 8 条。同一节点、同一 section、同一会话的新提议会覆盖旧的；超过 section 配额的文本直接拒绝。
    - **审批**：人在管理面用 `review-approve` / `review-reject` 处理，都是身份写入。批准默认仍按入队时的 sha 做 CAS，冲突时回 409，条目留在队列里；`rebase: true` 表示人看过 diff 后，基于当前版本写入。`GET ?name=` 在每个条目旁边附上该 section 的当前文本。
  - **CAS 的 sha 对模型可见**：`a2a:node:self` context 实时显示当前可变层的 sha，工具每次回复也都带 `current_sha256`。
  - **归因**：节点写入记 `by: node:<session>`、`via: node-tool`；人工批准记 `by: human:<who> approved[ (rebased)] node:<session>`、`via: review-approved`。
  - **日上限**：每个节点每个 UTC 日最多 8 次。按当天 `by` 以 `node:` 开头的版本计数；超出即拒绝，不进队列。
  - **本会话的回显**：写入成功后，记进本会话的 `a2a:node:self` 实时 context；冻结的系统提示词不变。
- **实现说明（N6）**：
  - **核对时机**：登记时核对一次；插件加载后立即全量核对一遍，否则不到 12 小时就重启的宿主永远轮不到全量核对；之后每 12 小时全量核对一次。
  - **核对的规则**：结束了的指针不再核对，代价是重开的 issue 会一直显示为已结束。同一指针同一时刻只有一次核对。已结束的状态不会被迟到的答复改回 open。插件卸载后，还在途中的核对不写盘、不提醒，因为文件此时已归新实例。
  - **复盘提醒**：只提醒「登记之后才结束」的指针：本地记录是 `open`，或者 GitHub 上的 merged_at / closed_at 晚于登记时间 `since`。登记前就已结束的、结束时间无从判断的，都不提醒；`unknown` 从不提醒。提醒用 followup 发给挂着该节点的活会话，并带上发送方标签。如果当时没有一个会话挂着这个节点（例如宿主冷启动，加载后的那次核对比会话上线早），就在指针上记 `remind_pending`，等这个节点下次挂到会话上时补发，然后清掉标记。补发的提醒挂到下一轮，不唤醒会话。比较结束时间用的是宿主的时钟：时钟偏差几分钟，可能让「登记时就没核对上」的指针多一次或少一次提醒。
  - **上限**：超出 64 条时，先淘汰已结束的指针，再淘汰最老的 open 指针。
  - **手改过的文件**：形状不对的行（包括 `since` 不是 ISO 时间的）读入时丢弃，丢弃前先备份成 `.dropped-<ts>`。
  - **任务状态 context**：`a2a:node:tasks` 实时读取，不冻结。正文同样经变量代入，`{{x}}` 不会让组装失败；文本 provider 抛错时，这一段为空。
  - **按版本聚合**：结果指标按版本聚合的统计面不在 N6，留给工作台。

## 7. 不做的事

- 不另建任务状态系统：状态以 GitHub 为准，节点只存指针。
- 不做重隔离：同一主机上的模型与主机属主同等可信。所以 §2 的 apiKey 强制挡的是「无意中调用」和「远端诱导」，挡不住同机上蓄意的 shell 写文件。这一点如实记在这里。
- 不让模型给自己或别的节点起名，不让模型改职责、红线和不可变层（#58）。
- 不依赖 DSH 的实验接口，不直接调 `ctx.agents.*` 去物化会话，不改 DSH 本身。
