# 2026-10-19 · 发布闸门：3081 先行 + 用户校验（稳定期不自动发版）

## 上下文

0.6.2（工作台×规划板合并 shell）在未走任何用户校验的情况下直接 `npm publish` 并部署
三机（.157/.85 全量、.156 预装）。用户随即立规（2026-10-19 13:07）：

- 「应先在3081进行测试，等我校验通过才能发布，更新工程开发习惯」
- 「原因是 稳定期的运维，不需要自动发版」

## 决策

1. **稳定期不自动发版**：发布不是改动的自动后果，是用户批准的事件。
2. 候选版本一律先部署 3081 测试环境（`DSH_HOME=D:/dsh-test-homes/3081`，端口 3081），
   用户校验通过后：`npm publish` → 生产部署 → 跨机验证。
3. 纪律固化于 `docs/release-gate.md`（标准流程 + 3081 环境事实）。

## 后果

- 0.6.2 属流程违例的既成发布：补做 3081 部署与用户校验；未过校验前不再有任何新发布。
- 3081 profile 顺带现代化（核心 deps 解 pin 对齐生产形态、修 Temp tgz 死指针、清孤儿
  patch、移除 peer 不兼容的 dsh-tool-gitbash）；dsh-loop/cli-manager 装后跳过（同生产）。
- 后续每个版本的定义 of done 增加「用户 3081 校验通过」一项，置于 publish 之前。
