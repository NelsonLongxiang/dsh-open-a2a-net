# ADR：a2a-net 作为 superagent 的跨节点端口实现

状态：提议，仅设计。配套 [接入规格](superagent-a2a-spec.md)。

## 上下文

dsh-superagent 是单仓库、单主机的工作智能体：从 Source 接活，经 Eval 授权开工单，通过 Executor 执行，经 Channel 回复。它不负责节点发现、调用方身份真伪和跨主机投递；架构文档还把“Trigger 字段可信度”列为开放问题。

dsh-open-a2a-net 已经具备签名身份、入站校验（失败拒绝）、正式回执、账本守恒、强制对账与 3 笔欠账背压。截至 0.7.0 及下一版本候选，还补上了接纳与记账状态的如实观察（receiverBookkeeping、占位 DELIVERED、acceptance）。

两者的分工天然互补。可选做法有三种：只借鉴概念、替换现有流程、做成它的端口实现。属主判断：a2a-net 就是为 superagent 准备的基础设施。

## 决策

把 a2a-net 实现为 superagent 的两个端口，接入时不改它的领域模型：
- 先做 a2a Source（入站）；
- 再做 A2A Executor（出站）。

a2a-net 一侧只补三样东西，都是读取面和观察面：
- 调用方自持游标的可重放读取；
- 发送结果分类；
- 按 context 读取对话。

另外定型 CLI 身份的正式回执命令。

不新增任务状态，不改回执与准入契约，不放宽背压。每个阶段先过非作者评审和全局放行，影子模式运行满 7 天无异常后，才处理真实请求。

## 后果

正面：
- superagent 获得跨节点的可信身份和可对账的投递；
- a2a-net 获得一个现成的接活、开工单、对人说话的上层，席位协作可以逐步标准化。

负面：
- 新增一个专用 CLI 身份要运维，包括户口续期和信箱容量；
- attention 借用“回执 + 新任务”表达，往返多一次；回执上要加 outcome 观察字段（S14）；
- 远端执行器没有 progress 中间报告。

推迟项：
- 远端执行器的进度可见性；
- 信箱 64 行上限是否调整（被挤出的消息不可恢复）；
- Gitea 等镜像通道不在本稿范围内。

已裁定（见[规格第 6 节](superagent-a2a-spec.md)，断言 S13）：
- 代码位置：本仓 next/0.8 上独立导出的插件包；
- 路由席暂不从评审席拆出。
