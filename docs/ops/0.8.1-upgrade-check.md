# 0.8.1 升级 / 回退 / 可复现候选检查

## 授权边界

目标 0.8.1-preview.24（0.8.1 的预览版，npm 上用 `preview` 标签，`latest` 不动），取代已打标签、未发布的 0.8.0；npmjs 上相对 v0.7.0。本文是"可发布"材料，不是已发布或已部署的声明：不打 tag、不 publish、不改生产配置、不碰凭证。发版 PR 经非作者精确头评审 PASS 后合入；tag、registry 发布与各节点部署由属主另行安排。

公开命令里的目录、服务入口和节点都用占位符，执行者替换成自己的已核准值，不在公开报告里回填网络或环境细节。

本版沿用 [0.8.0 升级检查](0.8.0-upgrade-check.md) 的全部内容；下面只写差别。

## 1. 宿主下界

- 插件本身与 superagent 团队的宿主要求同 0.8.0 §1。
- 新增：智能体预设随 bundle 层安装（`dsh plugin add` 把包的 `cordis.patch.yml` 合进 profile 的 bundles 层），用宿主的 `@deepseek-ai/dsh-agent-preset`。预设核对用宿主预设注册表的 `inspectCompositions`；缺它时不拦截设置，只靠角色工具守卫。验证宿主：DeepSeek Harness 桌面版 0.2.2-rc.1，`agentPresets/list` 列出 `superagent-router` 与 `superagent-member`。

## 2. 回退兼容

- 回退目标是 0.7.0（0.8.0 未发布）。账本、信箱与回执格式相对 0.8.0 没有变化，[回退复核 fixture](../../tests/fixtures/080-rollback-check.mjs) 原样适用，结论同 0.8.0 §2。
- 新增的持久化只在 `<a2a home>/superagent/`：设置里的 `repos`（成员 → 仓库）与执行器文件里的 `repos`（工单 → 仓库）。0.7.0 不读这个目录；重新升级后原样可用。
- 已在跑团队的宿主升级到 0.8.1：团队变为未绑定（存着的总工保留、存着的成员池丢弃，在途工作不动）。属主在画布上组队（总工与成员须在 `superagent-router` / `superagent-member` 预设下）并在「团队」页绑定画布与总工；请求方改发画布地址 `<zone>/canvas/<名字>`；成员主机用 `serve { team: '<zone>/canvas/<名字>@<fp8>' }` 重新服务（旧的 `serve-team` 已取消；预设前存下的服务关系若会话不是成员预设，不再接新活，状态报 `servesProblem`）。
- 设置文件新增 `canvas` 与 `serves.team`；0.7.0 不读 `<a2a home>/superagent/`，回退不受影响。

- `superagent` 默认开启：没写这个键的主机升级后运行团队引擎。回退到 0.7.0 后不再运行，状态目录保留。
- preview.3 在这个目录里新增 `decisions.json`（决策卡），新增的团队放在 `teams/<id>/` 下；原团队的数据不动。回退到 preview.2 后，新增的团队和决策卡不再生效，目录保留。
- preview.2 在这个目录里新增 `rule-changes.json`（规则提议、版本、最近修改），设置里新增 `profiles` 和 `dispatch`，0.7.0 同样不读。
- 预览版在这个目录里还多三样，0.7.0 同样不读：`pr-follow.json`（已读过的 PR 评论编号）、`reviews.json`（送审记录）、设置里的 `allowed.github` 与 `reviewer`。
- 预览版移除了 native-teams 桥（`nativeTeamsA2a` 服务接口）和办公室舞台（`/__dsh_a2a_canvas`）。回退到 0.7.0 后它们恢复；依赖这两者的宿主升级前要先改掉。

## 3. 洁净双导出、独立安装与可复现打包

流程同 0.8.0 §3；候选提交以发版 PR 合入 master 后的合并提交为准，证据在该提交上留存。

## 4. 开启 superagent 的节点

同 0.8.0 §4，但团队的组成与地址按 v5：在 `superagent-router` 预设下新建总工会话，在 `superagent-member` 预设下新建各成员会话；在规划视图把它们组成一支画布团队（其他主机的成员以远端槽加入，成员主机执行 `serve`）；到「团队」页绑定这支画布并指定总工；按仓库分工时给成员填 `repos`。团队地址是画布地址，团队内部句柄不对外。

## 5. 工单跟随 PR 与送审（可选）

- 想让工单跟随 PR：在团队宿主上用运维者自己的账号登录 `gh`，确认能读目标仓库。没有登录时工单保持打开，「团队」页显示读取失败的原因。
- 想让 PR 上的评论算人：在设置里把属主的 GitHub 登录名写进 `allowed.github`。默认为空。
- 想送审：在设置里写 `reviewer`（A2A 地址，须在属主的链接集内）。默认为空，不发任何请求。

## 6. 预览版发布

- 只发打包验收过的那一个 tgz，并显式带标签和作用域 registry：

```sh
npm publish "<AUDITED_TGZ>" --tag preview --registry=https://registry.npmjs.org --@nelsonlongxiang:registry=https://registry.npmjs.org/
```

- 读回时确认 `dist-tags.preview` 是 `0.8.1-preview.24`，且 `dist-tags.latest` 仍是 0.7.0。
- 安装时写死版本号：`@nelsonlongxiang/dsh-open-a2a-net@0.8.1-preview.24`。
