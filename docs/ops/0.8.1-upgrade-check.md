# 0.8.1 升级 / 回退 / 可复现候选检查

## 授权边界

目标 patch 0.8.1，取代已打标签、未发布的 0.8.0；npmjs 上相对 v0.7.0。本文是"可发布"材料，不是已发布或已部署的声明：不打 tag、不 publish、不改生产配置、不碰凭证。发版 PR 经非作者精确头评审 PASS 后合入；tag、registry 发布与各节点部署由属主另行安排。

公开命令里的目录、服务入口和节点都用占位符，执行者替换成自己的已核准值，不在公开报告里回填网络或环境细节。

本版沿用 [0.8.0 升级检查](0.8.0-upgrade-check.md) 的全部内容；下面只写差别。

## 1. 宿主下界

- 插件本身与 superagent 团队的宿主要求同 0.8.0 §1。
- 新增：智能体预设随 bundle 层安装（`dsh plugin add` 把包的 `cordis.patch.yml` 合进 profile 的 bundles 层），用宿主的 `@deepseek-ai/dsh-agent-preset`。预设核对用宿主预设注册表的 `inspectCompositions`；缺它时不拦截设置，只靠角色工具守卫。验证宿主：DeepSeek Harness 桌面版 0.2.2-rc.1，`agentPresets/list` 列出 `superagent-router` 与 `superagent-member`。

## 2. 回退兼容

- 回退目标是 0.7.0（0.8.0 未发布）。账本、信箱与回执格式相对 0.8.0 没有变化，[回退复核 fixture](../../tests/fixtures/080-rollback-check.mjs) 原样适用，结论同 0.8.0 §2。
- 新增的持久化只在 `<a2a home>/superagent/`：设置里的 `repos`（成员 → 仓库）与执行器文件里的 `repos`（工单 → 仓库）。0.7.0 不读这个目录；重新升级后原样可用。
- 已在跑团队的宿主升级到 0.8.1：总工与成员的会话要先改到 `superagent-router` / `superagent-member` 预设，否则下一次保存设置会被拒绝（已保存的设置照常运行）。
