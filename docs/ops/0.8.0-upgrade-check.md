# 0.8.0 升级 / 回退 / 可复现候选检查

## 授权边界

目标 minor 0.8.0，相对 v0.7.0。本文是"可发布"材料，不是已发布或已部署的声明：不打 tag、不 publish、不改生产配置、不碰凭证。发版 PR 经非作者精确头评审 PASS 后合入；tag、registry 发布与各节点部署由属主另行安排。

公开命令里的目录、服务入口和节点都用占位符，执行者替换成自己的已核准值，不在公开报告里回填网络或环境细节。

## 1. 宿主下界

- **插件本身：与 0.7.0 相同。** peerDependencies 没有变化，最低宿主包族仍是 `@deepseek-ai/dsh-agent >=0.1.7-alpha.2`，实际运行的 Agent 必须提供 `followup(UserMessage)`。依据与只读核对命令见 [0.7.0 升级检查](0.7.0-upgrade-check.md) §1，本版沿用。
- **superagent 团队（可选，`superagent: true`）：**
  - 验收所用宿主：DeepSeek Harness 桌面版 0.2.2-rc.1。
  - 开发与测试依赖：`@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-agent` 0.1.7-rc.2。
  - 用到宿主的 `agent/inbox/claimed` 事件（0.7.0 起已在用）、工具运行时的 `tools.get(name, scope)` 与 `tools.restrict`，以及会话作用域。
  - 缺 `restrict` 或作用域时，角色工具只靠全局守卫拒绝调用，不隐藏工具，并记一条日志。
  - 不开 superagent 的宿主不受影响。

## 2. 回退兼容：真实 0.7.0 包

从 npmjs 精确版本下载真实打包产物：0.7.0 SHA-1 `3e633c89a8064707707aa72b495fd2f05c29f093`。

[回退复核 fixture](../../tests/fixtures/080-rollback-check.mjs) 只写一个全新的空输出目录：

- 先用候选的真实 TaskLedger 写入：
  - 一笔出向欠账；
  - 一笔被 `acknowledged` 回执确认的欠账；
  - 一笔先确认、再被结果结清的归档行；
  - 一笔 attention 回执结清的归档行。
- 再用候选的 CliDepositStore 写两条带 `task_id`、`context_id`、`disposition`、`proof`、`receipt_for`、`admission` 的信箱行。
- 然后加载 0.7.0 包内未经修改的 `lib/task-ledger.js` 与 `lib/cli-deposit.js`：先只读，再由旧实现写一次，比较欠账 id 和字段。最后让候选重读旧版写过的信箱。

```sh
npm pack @nelsonlongxiang/dsh-open-a2a-net@0.7.0 --registry=https://registry.npmjs.org --@nelsonlongxiang:registry=https://registry.npmjs.org/ --ignore-scripts --pack-destination "<ARTIFACT_DIR>"
tar -xzf "<OLD_070_TGZ>" -C "<EMPTY_OLD_EXTRACT_DIR>"
node "<CANDIDATE_SOURCE>/tests/fixtures/080-rollback-check.mjs" "<CANDIDATE_PACKAGE_ROOT>" "<OLD_EXTRACT_DIR>/package" "<NEW_EMPTY_OUTPUT_DIR>"
```

实测结论（Node v26.12.0，macOS；最终候选包按同一 fixture 再跑留证）：

| 项目 | 真实 0.7.0 的行为 |
|---|---|
| TaskLedger 初始化 / 只读 | 成功；只读不改磁盘；两笔欠账（含已确认的那笔）都在，两条归档行都在 |
| 0.7.0 写一次之后 | 欠账 id 不丢；已确认欠账丢 `acknowledgedAt`；归档行丢 `disposition`（attention 行显示为未分类），先确认后结清的行还丢 `acknowledgedAt` |
| 已确认欠账的过期 | 0.7.0 不认识确认：按派发时间 24 小时后成为死信，而不是确认后 7 天 |
| CLI 信箱 | 两条行都读得出；新字段 0.7.0 原样保留，写一次也不丢；候选能重读旧版写过的信箱 |
| `<a2a home>/superagent/` | 0.7.0 没有读取方，不读也不删；重新升级后原样可用 |

结论：回退不丢欠账，但会丢确认信息。开了 superagent 的团队宿主回退前，应先让在途工单结束；否则请求方那边已确认的欠账会在 24 小时后成为死信。和 0.7.0 一样，不能在活跃的 0.8.0 home 上直接降级覆写：先在停写一致性窗口备份完整 home，回退时整套恢复，见 [0.7.0 升级检查](0.7.0-upgrade-check.md) §2。

## 3. 洁净双导出、独立安装与可复现打包

流程与 [0.7.0 升级检查](0.7.0-upgrade-check.md) §3 相同：

1. 同一候选提交 `git archive` 到两个全新空目录 A、B；
2. 各自独立 `pnpm install --frozen-lockfile --ignore-scripts` 与 `pnpm run build`；
3. `npm pack`，比较两份 tgz 的 sha256 与文件清单；
4. 确认包内没有陈旧 lib。

候选提交以发版 PR 合入 master 后的合并提交为准，证据在该提交上留存。

## 4. 开启 superagent 的节点

- 配置：在 a2a 插件配置里加 `superagent: true`，然后在工作台「团队」页的设置里指定总工与成员。成员是已有的会话，superagent 不会新开会话。
- 状态：团队状态写在 `<a2a home>/superagent/`，团队地址的 CLI 身份在其下的 `team-cli/`。
- 跨主机成员：两边要互为已链接的对等主机。成员一侧用 serve-team 指向团队宿主，团队一侧用 add-remote-member 登记成员；两边都钉住对方节点的公钥。
- 只读核对：`GET /__dsh_a2a/superagent` 看设置、工单、拒绝计数和健康状态，`a2a-net superagent state` 是终端里的同一视图。
