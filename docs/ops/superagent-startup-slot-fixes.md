## 1. Jobs.list 接收对象

`memberTurnFrom` 从服务取出 `list` 后裸调用，会丢失实例接收对象。当前安装版 `LocalJobRegistry.list` 依赖 `this.store`，不能假定它是已绑定函数。

最小修复是 `list?.call(jobs, id)`；不改变 owner、running/stopping 过滤，不将真实注册表异常吞成 `quiet=true`。

新增 `tests/unit/superagent-session-reads.spec.ts`：

- 接收对象保留，调用方 session 参数保持；
- 无作业、本人的 running/stopping/完成状态、他人和无属主作业；
- 缺少服务/方法的兼容路径；真实读失败仍抛出；
- 并发上限 1，成员报告 waiting 并结束 turn 后，原 assignment 留在 parked、任务未结束，下一票取得原执行槽。

安装版注册表兼容检查使用真实 `LocalJobRegistry.prototype.list` 和仅含空 `store` 的隔离对象，不创建作业生产者、不启动宿主：裸方法对照抛错，修后编译的产品 reader 返回 quiet。该检查不等同于真实业务会话验收。

## 2. cardCache 初始化时序

真实 `apply`/Cordis fiber 的合成持久化夹具复现出：已有 root agent 在 bundle 启用时触发 `syncRoleTools -> ofSession -> roleOf -> settings -> canvasTeam`，在缓存声明前访问它。

两条已复现路径：

1. 配置 seed 后，本地句柄解析 `localHandleResolver` 读取缓存；
2. 已钉公钥的远端画布成员解析读取缓存。

这两条路径不要求开放工单。因此不是仅重新覆盖历史 #617/#628 的 seatOf 或 named.tick 场景。修复将原缓存 Map 初始化移至消费者之前，保留同一缓存、同一发现/验签/准入语义，不吞异常或清空持久化状态。

新增 `tests/wire/superagent-persisted-activation.spec.ts`：无 seed 本地画布对照、配置 seed、已确认远端成员、持久化 waiting assignment 四种状态；每种加载、卸载、再次加载，并核对业务状态文件字节未变。外部 ygl CLI 及引擎启动在本夹具中显式替换，真实同步角色/画布解析/插件 fiber 保持；不宣称覆盖 pluginManager API、完整冷启动、后台模型或实际 ygl 迁移。

## 3. 名册接收与执行资格

现有 #610 已从 worker 池排除 `bots.a2a` 中的远端句柄。`teamRoster` 只描述接收名册能力，不能当作执行能力证明或自动排除条件；bot 名单又关联来源资格，不能为了隐藏 worker 自动加入。

本轮仅在市场接入清单和技能参考中明确三者差异，保留现有远端员工兼容性、签名和接单规则。若需要独立“仅收件端”配置，另行设计与评审，本轮未实现。
