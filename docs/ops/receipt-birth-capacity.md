# 回执出生预留与归档轮转

## 故障与修复边界

投递对应关系保留 512 条／24 小时，任务归档只保留 64 条。旧实现以“不在当前任务或归档中”判断未建账出生；已结算投递滑出归档窗口后会重新成为出生预留，累计64条即触发 `receipt-protected capacity is full`，即使真实 owed book 为空、对应表尚未满512。

修复给本地投递身份增加可选 `terminalRecorded: true`，仅真实 receipt、echo、cancelled 或 abandoned 终态提交时写入；evicted不是终态完成证据。标记与原结算同一持久化提交，失败一起回滚。归档轮转后标记仍随原task/message/fingerprint身份保留，不删除对应关系、不修改512/24h或回执保护64上限。已终结身份拒绝重新投递及重新建债；原消息身份冲突检查仍先执行。

## 旧账本与恢复限制

恢复只从快照中仍存在且明确带有受认可endedBy的归档行补证；不因claimed、consumed、年龄或窗口缺失就推断完成。没有终态证据的旧记录继续按原规则保护。恢复本身不为这个迁移写盘；下一次合法提交保存本地补证。

因此安装修复并不保证立刻解除一个已满的旧账本。对已经丢出归档的身份，须等现有保留期自然过期，或另行设计有完整证据、授权和回滚的恢复操作。已经存在的孤儿（有投递对应、却既无账本行也无归档行的出生），可由属主经 #824 的作废入口（`voidOrphanDeliveries`，浏览器操作，逐条留审计记录）处理，或等 24 小时保留期到期；作废只针对当前确属孤儿的身份，不是给已结算身份补证的途径。禁止手改真实账本、批量标完成、伪造回执、增加容量或缩短TTL来腾位。重启也不是恢复证明。

## 工程检查

回归位于 `tests/unit/receipt-birth-capacity.spec.ts`，经既有 `verify-temp-clean` 入口运行：覆盖归档轮转、重启、真实出生保护、持久化失败回滚、旧快照有据迁移/无据保守、evicted不当终态、伪造字段拒绝、原512/24h边界和重放拒绝，以及 echo 结清同样记证、同 id 仍有在办行时不记证、只给 taskExpected 的出生记证。`tests/wire/receipt-birth-archive-replay.spec.ts` 先删掉幂等存储（相当于其 TTL 已过）再经真实 HTTP 重放，只由投递身份上的终态证明拒绝；幂等存储还在时重放在那一层就以 409/-32003 被拒，与本修复无关。原ledger、receipt-outbox、followup及capacity suites一并复验。工程检查不替代正式spec-run、非作者评审或运行宿主验收。
